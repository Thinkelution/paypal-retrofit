The problem

Most businesses already have a system. It just doesn't talk to PayPal.

A booking tool, an old invoicing app, a spreadsheet, a homegrown ERP. PayPal's Agent Toolkit lets an AI agent call PayPal, but nothing helps an agent connect PayPal to a system that was never built for it. So invoices get re-typed, payments get marked by hand, and the two sets of books drift apart.

Integration takes a week

Someone has to learn the PayPal API and write glue code against a schema they didn't design.

Payments never flow back

Without webhooks wired to the old system, staff reconcile by eye and mark invoices paid manually.

Agents are risky with money

An AI that can call payment APIs directly is one bad prompt away from a refund nobody approved.

How it works

Map, sync, reconcile. The old system stays in charge of its data.

1

Point it at the database you already have

The Mapper agent reads the schema and a few masked sample rows, then proposes how customers, services, invoices, line items and recurring agreements become PayPal objects. Every choice comes with a reason. Nothing touches PayPal until you accept.

  • SQLite, Postgres, or a folder of CSV exports
  • Validated against the real schema; falls back to a deterministic mapper
  • Editable later in the console

2

Send open invoices through PayPal, with your own numbers

sync plans every change, then creates PayPal invoices that keep the business's invoice numbers, emails each customer a pay link, and writes the PayPal id and link back into the columns the mapping allows. Voided invoices are cancelled; invoices paid outside PayPal are recorded so customers aren't asked twice.

  • Idempotent: re-running never duplicates an invoice
  • Pending retainers become PayPal subscriptions
  • Drafts stay where they are
3

Payments flow back on their own

When a customer pays, PayPal's webhook is checked with PayPal's own signature verification, stored once, and applied to the legacy record (status, paid date and amount) before PayPal is told it arrived. If a webhook is ever lost, the reconciler finds the payment and repairs it, and flags anything that needs a person.

  • Verified with verify-webhook-signature
  • Disputes, refunds and failed renewals become discrepancies
  • Reconciles every 5 minutes, or on demand
Architecture

A deterministic engine moves money. Agents propose and explain.

Every PayPal write is an action with an idempotency key, a reason a person can read, and the policy that decided it. The agents only ever see read tools and one write tool: propose_action.

Idempotent everywhere

PayPal request ids derive from the record and its content hash; one link per legacy record; one application per webhook event.

Never trusts a payload alone

On every invoice event, retrofit re-reads the invoice from PayPal before writing anything back.

Recoverable by design

Webhook failures return 500 so PayPal retries; the reconciler is the backstop for anything still missed.

AI agents

Claude agents, one job each.

Built with Claude through the official Anthropic SDK. The default model is claude-opus-5-5.

Integration

Mapper

Turns an unfamiliar schema into a typed PayPal mapping with structured outputs.

  • Reads tables, keys, status values and masked samples
  • Classifies every status as open, paid or cancelled
  • Finds safe columns for write-back, never repurposes data
  • Explains each choice and flags low confidence
Operations

Ops

Works the receivables in plain language, using the SDK tool runner.

  • Ledger search and read-only SQL on the legacy database
  • PayPal reads through PayPal's Agent Toolkit
  • Batches reminders, recorded payments and refunds as proposals
  • Runs the collections playbook; a writer drafts each reminder in the right tone
  • Only claims an action happened when the engine says it ran

Safety

The owner decides what an agent may do with money.

Every side effect, whether it comes from sync, an agent or a button, is an action decided by a policy. The defaults are conservative and can be changed per action in the console.

ActionDefault policy
Create, send, update invoicesauto
Send remindersconfirm
Record a payment made outside PayPalauto up to 250 USD, then confirm
Cancel an invoiceconfirm
Refund up to 100 USDauto within 500 USD a day
Larger refundsconfirm
Offer a payment planconfirm
Create or cancel a subscriptionconfirm
Accept a dispute claimnever
  • Personal data is masked before it reaches a modelEmails, phone digits and street numbers are hidden in schema samples and tool results.
  • Agent SQL is read-onlyA single SELECT on a read-only connection or read-only transaction.
  • Writes only where you allowRetrofit never alters the schema and only fills the write-back columns named in the mapping.
  • Quiet hours and daily capsReminders approved out of hours wait for the morning; automatic refunds and reminders stop at a daily limit and ask a person.
  • Sandbox firstProduction mode is refused unless it is explicitly enabled; secrets live only in the environment and are redacted from logs.

Quick start

Try it in two minutes. No accounts needed.

The demo runs Fernhill Studio's legacy app, a local stand-in for the PayPal endpoints and the console in one process.

# Node 20+ with corepack
$ git clone https://github.com/Thinkelution/paypal-retrofit.git
$ cd paypal-retrofit
$ corepack enable && pnpm install && pnpm build
$ pnpm retrofit demo --fresh

paypal-retrofit demo (mock PayPal, no account needed)
  Dashboard     http://localhost:8787/
  Legacy app    http://localhost:8787/fernhill

# your own system, against the PayPal sandbox
$ cp .env.example .env    # PayPal sandbox app + ANTHROPIC_API_KEY
$ pnpm retrofit init --source postgres://…   # or sqlite:… / csv:…
$ pnpm retrofit sync --dry-run
$ pnpm retrofit serve

Turn on the agents

Add ANTHROPIC_API_KEY to .env. Without it, mapping uses the deterministic mapper and the agent panel stays off.

FAQ

Questions

Does it change my database?

No schema changes, ever. Retrofit reads your tables and writes only to the columns your mapping names, such as a PayPal invoice id or a paid date. If you have no such columns, it keeps the links in its own state store. For CSV sources it writes to sidecar files and leaves the originals untouched.

Do I need a PayPal account to try it?

No. The demo ships with a local stand-in for the PayPal endpoints retrofit uses, with signed webhooks and customer pay pages. To use the real PayPal sandbox, create a free developer app and run the demo with --sandbox.

Can the AI move money on its own?

Only within rules you set. Agents can only propose actions; each kind of action has a policy (auto, confirm or never), optionally by amount, with daily caps. By default small refunds run on their own, larger ones, cancellations and reminders wait for your approval, and accepting disputes is refused.

Do I need to be technical?

No. Run paypal-retrofit serve (or use a hosted copy) and the console opens a four-step setup wizard: upload CSV exports, check the mapping, choose your rules in plain words, preview, go live. After that the morning digest comes to your inbox or Slack, and you approve things from your phone.

Can I use it from Claude Desktop or Claude Code?

Yes. retrofit is an MCP server: paypal-retrofit mcp over stdio, or /mcp over HTTP. Your Claude gets the same tools and the same rules as the built-in agent; anything that needs your OK still waits for it. Approving from the client is off unless you turn it on.

Which AI model does it use?

Claude through the official Anthropic SDK, defaulting to claude-opus-5-5. You can choose another model with RETROFIT_MODEL.

Is it production ready?

Not yet. It is built and tested against PayPal's sandbox APIs and refuses production mode unless explicitly enabled. Treat it as a strong starting point, not a finished payments product.

Is this an official PayPal product?

No. paypal-retrofit is an independent open-source project built on PayPal's public APIs and Agent Toolkit. It is not affiliated with or endorsed by PayPal.
